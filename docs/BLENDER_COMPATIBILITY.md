# Arena / Blender CPU compatibility audit

**Scope:** this Arena checkout and standard `ubuntu-24.04` GitHub Actions CPU jobs, reviewed 2026-11-18. Upstream claims are not treated as local test results.

The checkout already had `.claude/skills/`, a display-less `bpy` setup in `singularity-bloom/`, an unfinished Lantern Tide scene, and separate Pages and browser-video workflows. Arena exposes repository reads and shell execution. The Blender and GitHub **connector** probes returned unsupported in this session; authenticated Git and `gh` still work via the shell. The tools exposed here do not show a way to register an arbitrary stdio/HTTP MCP server or install a Claude/Codex plugin into Arena itself. Markdown can be read directly; no skill auto-discovery was assumed or tested. This is a statement about this session, not every Arena deployment.

Locally I observed Debian 12 x86_64, Python 3.11.2, 2 visible CPUs, about 3.8 GiB RAM, no graphics device nodes, no `blender`/`ffmpeg` commands on `PATH`, and missing X/GL libraries for the wheel. The existing project's local-only shim was used to load official `bpy` for **Cycles CPU** in this stripped container. It is not proof of graphics or GPU support. GitHub jobs install real system libraries, not the shims, and use CPython 3.11.18 and hash-locked wheels.

## Limits and CPU alternatives

| Don't assume on standard hosted CPU workers | Verified or appropriate CPU substitute |
|---|---|
| CUDA, OptiX, HIP, Metal, oneAPI **GPU** rendering or hardware video encode | Cycles CPU + OpenImageDenoise, adaptive sampling, tiled larger frames, and libx264 software encoding. More cores or actual GPU hardware for high throughput. |
| Eevee/realtime viewport features in a plain headless container | Cycles CPU look-dev stills and contact sheets. Eevee needs compatible graphics context/drivers; software graphics configurations are not supported by this pipeline. |
| Human brush sculpting/painting in a GUI or the user's existing desktop | Editable object-level subdivision and displacement, deterministic UVs and procedural PBR. Final brush work requires an interactive Blender session. |
| Fast feature-length 4K or dense smoke/fluid/destruction bakes | Preview at smaller resolution, reduce samples and simulation domain, checkpoint frame jobs; for demanding projects use more RAM, disk and/or persistent CPU/GPU workers. Not benchmarked here. |
| Paid plug-ins, services, or assets without access | Blender-native functions, procedural resources and open dependencies. No credential, payment, or license bypass. |

The integrated scope is a reproducible CPU path, not an MCP/desktop installation, unlimited render farm, or workaround for GPU-only algorithms. All workflow outputs are generated and ignored except the lightweight README preview.
