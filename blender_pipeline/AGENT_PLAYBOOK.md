# Agent runbook: headless Blender on CPU

Read this file deliberately through the repository tools. It is not an Arena plugin manifest and does not rely on automatic `SKILL.md` discovery.

1. **Check the runtime first.** The known path is official `bpy` 5.0.1 on CPython 3.11 and Cycles CPU. Check `bpy.app.version`, `bpy.app.background`, and installed shared libraries before using any example aimed at a later Blender release. Do not assume the availability of a Blender executable, UI, add-on, GPU, or local MCP host.
2. **Use Blender's data API for construction.** Name collections, use explicit mesh winding, set metric units, keep editable modifiers, and set a real camera, lights, and render settings in the file. Use operators only with a known context; check their return values. Use the evaluated dependency graph for tests of modifiers and instances.
3. **Shape procedurally, not with UI brushes.** Use a bounded base mesh, subdivision and noise displacement for sculpt-style details. In the sample, see `sculpt_erosion()`; it remains editable and its evaluated mesh is checked. Destructive voxel remeshing can remove UVs; preserve the original and budget the voxel size if adding it to another project.
4. **Validate UVs and materials separately.** The lighthouse strip has a longitudinal seam, padded side UVs, and independently packed caps. Its procedural Principled materials don't require any image files. If adding image PBR, use sRGB only for color maps and Non-Color for data maps; pack assets or fail preflight on missing external files.
5. **Prefer instance graphs and real keyframes.** The trail uses an editable `Instance on Points` graph and one small mesh prototype; do not realize the instances without a reason. Animate low-cost transforms before adding simulations. Check world transforms at several frames and read back the saved scene.
6. **Start with the `ci` profile.** Run the [pipeline](README.md), read the scene and media QA, inspect the poster/contact sheet, and only then raise resolution, samples or duration. Resume with the same bundle and receipts. Use disposable copies for untrusted `.blend` inputs; don't add remote code-execution services or secrets to render workers.

Guidance sources: [EL4CTEO/blender-skills](https://github.com/EL4CTEO/blender-skills/tree/9e7e04a603c125a0d17447ab97112fa70a865067/skills) (core, sculpt, UV, Geometry Nodes, animation and QA) and the [Scenario Blender expert family](https://github.com/scenario-labs/skills/tree/a14d061fe5db33d339b1d89f775f37337481295f/skills/dcc/blender) (headless review and delivery-gate approach). The small object-space displacement operation was adapted from EL4CTEO's `sculpt_ops.py`; the [MIT notice](licenses/EL4CTEO-blender-skills.txt) is retained. Everything else is project-local implementation; neither skill collection was installed wholesale.
